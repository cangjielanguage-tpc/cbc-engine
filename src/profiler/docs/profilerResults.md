# Анализ размера буфера профайлера при периоде сбора 10 мс

## Методология
Количество запусков каждого теста: 1

Период сбора профилировочной информации: 10 мс

Размер одного буфера менялся от `2^10` до `2^19`.

При размере буфера `2^19` профилировщик собрал все зарегистрированные вызовы во всех шести тестах.

В столбцах «Совпадение с топ-n» указано, сколько записей из профиля данного размера входит в соответствующий топ полностью собранного профиля `2^19`. 

Значение `m/n` означает `m` общих записей из `n`.

## Память

Одна запись содержит два `uintptr_t` и занимает 16 байт. Каждый `FiberProfile` содержит два буфера, поэтому общий размер буферов одного файбера равен `2 * 2^N * 16` байт.

Общая память, используемая профилировщиком равна произведению памяти на один файбер (2 буфера) и количества одновременно существующих файберов.

## Итоговый выбор

Цель профилирования — найти основные часто происходящие вызовы и определить функции, которые следует рассматривать в первую очередь для оптимизации. Для этой задачи не требуется собирать все вызовы или точно воспроизводить их абсолютные счётчики.

При `2^10` во всех тестах обнаруживаются основные часто вызываемые места. Для Chess, kXML, Parallel, PNG Decoding и Regular Expressions совпадает весь топ-10. В Cryptography формально совпадает только 1/10, но при этом совпадают 48/50 мест топ-50: низкое значение для топ-10 объясняется перестановкой многочисленных вызовов `DESEngine.desFunc` с одинаковыми или близкими счётчиками, а не потерей основной часто вызываемой функции.

Поэтому основной рекомендуемый размер — `2^10`, то есть 1 024 записи и 32 KB на файбер с учётом двух буферов. При периоде сбора 10 мс он даёт достаточную картину для поиска главных направлений оптимизации при минимальном расходе памяти. Проценты и точный порядок вызовов в таком профиле могут быть искажены, поэтому их не следует использовать для количественного сравнения близких по частоте мест.
